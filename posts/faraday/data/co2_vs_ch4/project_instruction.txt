# Faraday MCP Blog Post Skill

Produces a single self-contained HTML blog post that demonstrates the Faraday
MCP server end-to-end: real tool calls, real data, real calculations, interactive
visualizations, downloadable Parquet files, and full provenance transparency.

---

## Execution Phases

Work through these phases in order. Do not draft prose until Phase 1 is complete.
Do not finalize HTML until Phase 4 (review) is complete.

---

### PHASE 1 — DISCOVERY (run tools first, write nothing yet)

1. Use the Faraday MCP tools to query all six data sources. Execute at least
   one real tool call per source — no placeholders, no invented data.

2. **HARD CONSTRAINT**: ALL data must come exclusively through Faraday MCP tool
   calls. Do NOT fetch data directly from NIST, HITRAN, PubChem, or any other
   website via HTTP, browser, or any non-MCP route. If a source is unreachable
   via MCP, document the failure as a limitation — do not route around it.

3. Identify a scientifically meaningful cross-source use case requiring ≥4 data
   sources to answer one coherent question. Strong candidates:
   - Molecular energy budgets
   - Spectroscopic identification pipelines
   - Atmospheric opacity / radiative transfer
   - Astrochemistry cross-checks

4. Perform quantitative analysis using `scipy.constants` for all physical
   constants — no hardcoded values. Show the math.

---

### PHASE 2 — DATA PRODUCTS

For every dataset retrieved via MCP:

1. Serialize as Parquet using `pyarrow`. Include all returned fields — no
   truncated columns.
2. Name descriptively: `{source}_{entity}_{query}.parquet`
   e.g. `hitran_H2O_lines_600_1400cm.parquet`
3. Embed each file in the HTML as a base64-encoded download link. The page
   must be fully self-contained — no server required.
4. Build a data manifest table: source, filename, row count, columns, file size.

---

### PHASE 3 — ARTICLE STRUCTURE

Write a **10–15 minute read** with this exact section order:

| §   | Title | Content |
|-----|-------|---------|
| 0   | Hero | One-sentence thesis: what Faraday enables that wasn't easy before |
| 1   | Tool landscape | Each data source: what it is, what it covers, canonical use case. ≤1 paragraph each + summary table |
| 2   | Architecture overview | Mermaid diagram (Phase 6) + 2–3 paragraphs on call flow: client → MCP protocol → dispatcher → upstream APIs → return path |
| 3   | The use case | Scientific question, why multiple sources are required, step-by-step workflow with real data |
| 4   | Results | Quantitative outputs as interactive charts (Phase 5) |
| 5   | Data products | Manifest table with download buttons |
| 6   | Strengths | Honest assessment of what Faraday is genuinely good for |
| 7   | Limitations | Specific coverage gaps, resolution limits, failed MCP calls |
| 8   | Outlook | What a multi-agent pipeline using these tools looks like |
| App A | MCP calls | All tool calls as formatted JSON blocks |
| App B | Calculation code | Self-contained Python (scipy + pyarrow only); reads from Parquet files |
| App C | Prompt | The exact prompt that generated this article, verbatim |
| App D | Provenance | Generation metadata + footer callout (see below) |

### PHASE 4 — REVIEW & VERIFICATION (hard gate — do not finalize HTML until complete)

Treat this as a separate agent reviewing the drafting agent's work.

**Numbers**
- Re-derive every numerical result independently from raw MCP outputs and
  `scipy.constants` values. Correct any discrepancy.
- Check all unit conversions explicitly (cm⁻¹ → nm → eV → J etc.).
- Verify all order-of-magnitude estimates are physically reasonable.
- Confirm every constant matches its `scipy.constants` name and CODATA value.

**Calculations**
- Trace each formula in the prose to a line in Appendix B code.
- Run Appendix B mentally end-to-end; confirm outputs match §§ 3–4.
- Check for compounding rounding errors across multi-step calculations.

**Graphs and visualizations**
- Axis labels, units, and tick values must match the Parquet data.
- Tooltip values on hover must match the underlying data to full floating-point
  precision (display rounding is permitted but raw value must be in tooltip).
- Confirm zoom reveals additional point density — no downsampling.
- Spectral / energy-level diagrams must use actual retrieved values, not schematics.

**Mermaid diagram**
- Every edge tool name must match an actual Phase 1 tool call (exact spelling).
- Data flow direction arrows must be logically correct.
- Pan/zoom controls must be present and functional.

**Cross-checks**
- Manifest row counts match actual Parquet record counts.
- Appendix A JSON matches exact Phase 1 call parameters (no paraphrasing).
- Appendix C is verbatim prompt.
- Appendix D callout box is present in the footer with verbatim text.

**Audit trail**: Document every correction as an HTML comment:
`<!-- REVIEW: corrected X → Y -->`

### PHASE 5 — INTERACTIVE GRAPHICS (vanilla JS only — no charting libraries)

#### All charts (§ 4 and anywhere else data is visualized)

Implement as HTML5 Canvas or inline SVG + vanilla JavaScript.

**Zoom & pan**
- Mouse wheel / trackpad pinch → zoom both axes simultaneously (or per-axis for spectra)
- Click and drag → pan
- Double-click → reset to default view
- Must render ALL data points at every zoom level — no downsampling

**Data points & tooltips**
- Every discrete point rendered as a visible marker (circle / cross / diamond)
- Hover tooltip: x-value + unit, y-value + unit, source database, MCP tool name
- Tooltip follows cursor, does not overflow viewport
- High-density datasets (>500 points): 2px dots at full zoom-out, scale to 6px+
  when <50 points visible in the current view

**Axes & labels**
- Dynamic rescaling during zoom with correct tick intervals at every zoom level
- Labels include physical quantity name and unit
- "Current view range" readout below each chart:
  e.g. `Viewing: 667.2 – 668.1 cm⁻¹ · 14 points`

**Toolbar above each chart**
- `[Reset zoom]` `[Download PNG]` `[Copy data as CSV]`
- PNG download captures current zoom state
- CSV export contains only currently visible points at full precision

#### Mermaid diagram interactivity

Apply after Mermaid renders the SVG, via injected vanilla JS:

- Mouse wheel → zoom centered on cursor
- Click and drag → pan
- Double-click → reset to fit-to-container
- **Node hover**: tooltip with node description, associated tool name(s),
  one-line description of what data that source provides
- **Edge hover**: highlight the full call path (client → MCP → data source →
  return), dim all other edges and nodes
- Toolbar: `[Reset view]` `[Download SVG]`

**Call flow overlay**

**Rendering**
- Mermaid JS CDN: `https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js`
  (the ONE permitted external JS dependency alongside Google Fonts)
- Custom dark theme matching the article aesthetic
- Must be readable at 800px width without horizontal scroll
- Apply Phase 5 pan/zoom controller after render

### PHASE 7 — HTML DESIGN

Single self-contained HTML file. No server required.

**Aesthetic**: Dark scientific — deep navy/black background, instrument-readout
accent color, monospaced data elements.

**Typography**: Sharp serif for body (Source Serif, Lora, or Charter via Google
Fonts) + monospace for code and data.

**Interactions**
- All charts interactive per Phase 5
- Mermaid diagram pan/zoom + hover per Phase 5
- Smooth scroll, sticky nav
- Collapsible appendix sections (collapsed by default on screen)
- Parquet download buttons styled as terminal export actions

**Print**: `@media print` — appendices expand, charts render as static snapshots.

**External dependencies**: Mermaid CDN + Google Fonts only. All interactivity
is vanilla JS. Zero other external libraries.

## Quality Bar (failure conditions)

| Check | Failure condition |
|-------|------------------|
| Data sourcing | Any number not traceable to a Faraday MCP tool call or `scipy.constants` |
| Charts | Any static image where an interactive chart was required |
| Mermaid | Static diagram without pan/zoom and edge-highlight hover |
| Tooltips | Values that diverge from underlying data precision |
| Parquet files | Mock CSV embedded as fake Parquet |
| Review gate | HTML finalized before Phase 4 complete |
| Provenance | Callout box absent, softened, or paraphrased |
| Mermaid client node | Not labelled `Claude Opus 4.8 · Cowork · Max Effort` |
| Appendix B | Code that re-queries external sources instead of reading Parquet files |
| Limitations | No mention of MCP calls that failed or returned empty results |
